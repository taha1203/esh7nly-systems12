# ESH7NLY 3.2 — WhatsApp & Smart Management

نسخة مطوّرة مبنية على ملفات المشروع السابقة. تحافظ على إعداد Firebase الحالي ومسار البيانات دون تغيير:

- Firebase Realtime Database: `https://esh7nly-62354-default-rtdb.firebaseio.com/`
- مسار البيانات: `/esh7nly`
- ملفات الموقع: `index.html`, `script.js`, `style.css`, `register.html`

## الجديد في الإصدار 3.2

### WhatsApp
- إرسال للمشتركين المحددين.
- إرسال لكل النتائج الظاهرة بعد استخدام البحث والفلاتر (ومنها فلتر التاجر المشتري أو المورد أو الباقة).
- إرسال لكل العملاء في اليومين 11 و26.
- استهداف غير المسددين فقط.
- استهداف التجديدات التي موعدها خلال 5 أيام أو المتأخرة.
- قوالب رسائل محفوظة ومزامنة مع بيانات النظام.
- متغيرات الرسالة: `{name}`, `{number}`, `{package}`, `{dueDate}`.
- سجل حملات يوضح عدد المحادثات التي فُتحت، وليس عدد الرسائل التي تم إرسالها.
- فتح محادثة واتساب واحدة في كل مرة لتقليل الحظر من النوافذ المنبثقة وإتاحة مراجعة الرسالة.

**مهم:** الموقع لا يرسل رسائل واتساب تلقائيًا ولا يستطيع تأكيد التسليم. بعد فتح المحادثة يجب الضغط على إرسال داخل واتساب بنفسك. الإرسال التلقائي الرسمي يتطلب WhatsApp Business Platform وخادمًا خلفيًا وموافقة العملاء.

### المساعد الذكي الداخلي
- تحليل إجمالي العملاء والمبيعات والربح المحسوب.
- كشف الاشتراكات غير المسددة وقيمتها.
- رصد التجديدات خلال 5 أيام أو المتأخرة.
- تنبيه عند وجود سعر بيع أقل من تكلفة الباقة.
- تحديد الباقة الأعلى ربحًا حسب البيانات المسجلة.
- تجهيز مسودات رسائل للتجديد والعروض والسداد والترحيب.

هذا مساعد تحليلي محلي مبني على قواعد داخل الموقع، وليس نموذج GPT توليديًا أو اتصالًا بخدمة AI خارجية. ربط نموذج AI حقيقي يحتاج خادمًا آمنًا لحماية مفتاح API؛ لا تضع مفتاح API داخل `script.js` أو قاعدة Firebase العامة.

### تحسينات أخرى محفوظة
- حذف مشترك واحد أو مجموعة محددة مع تأكيد وتسجيل الحذف.
- إدارة الموردين والتجار المشترين كلٌ على حدة.
- تقارير الأرباح والتكاليف والتنبيهات والنسخ الاحتياطي.
- بوابة طلبات التسجيل السابقة كما هي.

## التحديث على GitHub Pages

1. افتح لوحة ESH7NLY وصدّر نسخة JSON احتياطية أولًا.
2. فك ضغط ملف ZIP.
3. افتح مستودع GitHub الحالي نفسه.
4. ارفع محتويات المجلد `esh7nly-system-main` إلى جذر المستودع، واستبدل الملفات المتطابقة.
5. لا تغيّر إعدادات GitHub Pages ولا رابط الموقع ولا مشروع Firebase.
6. انتظر اكتمال النشر، ثم افتح الموقع وحدّث الصفحة تحديثًا كاملًا.

## تنبيه أمان مهم

قواعد Firebase الحالية في المشروع الأصلي مفتوحة للقراءة والكتابة، وتسجيل دخول الإدارة محلي داخل المتصفح وليس Firebase Authentication. حافظنا على هذه الإعدادات دون تغيير لتجنب قطع المزامنة أو فقد البيانات، لكن لا تعتبر النظام آمنًا للنشر العام أو لمشاركة بيانات الدخول. قبل نشر بيانات حساسة أو تفعيل بوابة التسجيل للعامة يجب تنفيذ Firebase Authentication وقواعد وصول آمنة واختبارها مع الكود.

## فحص الإصدار

- فحص صياغة `script.js` باستخدام `node --check`.
- تم التحقق من بقاء رابط Firebase ومسار البيانات كما هما.
- لم يتم تغيير مخطط بيانات المشتركين الحالي؛ تمت إضافة حقول اختيارية لقوالب واتساب وسجل الحملات مع قيم افتراضية للبيانات القديمة.
